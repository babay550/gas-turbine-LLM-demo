# 产品需求文档: 燃气轮机运行优化智能体

**版本**: 1.5
**日期**: 2026-05-13
**作者**: zhurongjun (Product Owner)
**质量评分**: 90/100

---

## 概要总结

面向燃气轮机机组智能运维需求，基于数字化电厂建设中已有的能效分析、预警诊断、运行优化决策等小模型成果，构建运维智能体（Agent）化封装与协同调度系统。系统将设备监测诊断数据、技术知识库和小模型预警分析结果封装为**设备运维 Agent**，服务于机组智慧运维；将耗差分析、能效分析、机组对标分析等小模型结果封装为**运营优化 Agent**，服务于功率优化和热电协调。系统内置基于 Karpathy 知识管理范式的技术知识库，支持文档上传自动提取知识、生成结构化 wiki 词条，并通过知识图谱可视化呈现词条关联网络。

系统采用本地开源大语言模型（Qwen/ChatGLM 等），通过 LLM 框架（LangChain）搭建，前端基于 Vue 框架 + 2D/3D 引擎（Meta2d）构建运维操作仪表盘，首页以交互式燃机机组示意图呈现设备运行全貌，提供仪表盘 + 对话式混合交互界面，服务于运行值班员、设备工程师和运行优化工程师三类用户角色。

---

## 问题陈述

**现状**: 燃气轮机电厂已部署多个专业小模型（能效分析、预警诊断、耗差分析等），但各模型独立运行、缺乏统一调度，运行人员需要在多个系统间切换查看结果，知识分散、决策效率低。同时，现有小模型仅提供指标偏差结果，缺乏基于热力学原理的动态基准值模型来支撑实时能效监测，且无法从性能异常逐级归因至子系统/部件级根因，导致诊断停留在指标层面，难以精准定位设备根本原因。

**解决方案**: 构建智能体协同调度系统，包含两大核心能力层：(1) 能效监测数据层——建立关键参数动态基准值模型，实时计算各项能效指标并可视化；(2) 根因推理层——基于热力学仿真的逐级分解模型与融合因果图的根因推理引擎，将大模型的自然语言理解与专家规则库结合，实现从性能异常到设备根因的精准定位。Agent 化封装将上述能力统一调度，提供一站式智能运维交互体验。

**业务影响**: 提升设备故障预警及时性，加速运行人员问题定位速度，优化机组能效运行水平，降低非计划停机风险。

## 成功指标

**主要 KPI:**

- **预警准确性**: Agent 能正确调用小模型并以自然语言准确解读预警结果，准确率 > 90%
- **响应效率**: 运行人员通过 Agent 辅助定位问题的时间缩短 50% 以上
- **能效优化**: 运营优化 Agent 提供的功率优化建议被采纳率 > 70%
- **根因定位精度**: 逐级分解与根因推理引擎能将性能异常归因至子系统（压气机/燃烧室/透平）级，Top-3 根因命中率 > 80%
- **基准值模型准确度**: 动态基准值模型对关键参数的预测偏差 < 2%（满负荷工况下）
- **系统可用性**: Agent 系统正常运行时间 > 99%

**验证方式**: 在半山电厂燃气轮机机组上部署 Demo，通过实际运行场景验证。

## 用户角色

### 主要角色 1: 运行值班员
- **职责**: 机组日常运行监控、参数调整、异常初步判断
- **目标**: 快速发现异常、理解预警含义、获得操作建议
- **痛点**: 预警信息分散、需要跨系统查看、缺乏综合研判
- **技术水平**: 中等，熟悉电厂运行但不熟悉 AI 系统

### 主要角色 2: 设备工程师
- **职责**: 设备状态分析、故障诊断、检修决策支持
- **目标**: 深入了解设备健康状态、获取诊断分析报告、制定检修计划
- **痛点**: 诊断数据分散、历史案例检索困难、缺乏智能辅助
- **技术水平**: 中高，熟悉设备原理和数据分析

### 主要角色 3: 运行优化工程师
- **职责**: 机组能效监控、运行参数优化、对标分析
- **目标**: 获取能效分析结果、优化运行策略、提升机组经济性
- **痛点**: 多维数据分析复杂、优化建议缺乏可操作性
- **技术水平**: 中高，熟悉热力系统和经济运行

## 用户故事与验收标准

### 故事 1: 设备状态综合查询

**作为** 运行值班员
**我想要** 通过自然语言询问"当前 X 号燃机状态如何"
**以便** 快速了解设备整体运行状况，无需逐个查看多个系统

**验收标准:**
- [ ] Agent 能识别设备编号并调取时序数据库中的实时监测数据
- [ ] 返回包含关键参数（温度、压力、振动、功率）的综合状态摘要
- [ ] 对于异常参数自动标注并提供可能原因
- [ ] 响应时间: 简单查询 < 10 秒

### 故事 2: 智能预警解读

**作为** 运行值班员 / 设备工程师
**我想要** 收到预警后让 Agent 解读"这个预警是什么意思，严重程度如何"
**以便** 快速理解预警含义并判断是否需要采取行动

**验收标准:**
- [ ] Agent 调用预警诊断小模型获取预警详情
- [ ] 用自然语言解释预警的技术含义和严重等级
- [ ] 关联历史相似案例和处置建议
- [ ] 实时预警推送延迟 < 5 秒

### 故事 3: 能效监测与实时指标计算

**作为** 运行优化工程师
**我想要** 在仪表盘上实时查看机组各项能效指标及其与动态基准值的偏差
**以便** 及时发现能效劣化趋势并采取运行调整措施

**验收标准:**
- [ ] 系统对接监测数据接口，获取燃机功率、热耗率、压气机出口压力和温度、透平进气压力和温度、排气温度等关键参数
- [ ] 基于动态基准值模型，为每个关键参数生成随工况变化的基准曲线
- [ ] 实时计算并展示发电气耗、压气机效率、燃烧效率、透平效率、热耗率、发电效率、联合循环效率等关键能效指标
- [ ] 仪表盘展示指标趋势图，偏差超阈值时高亮预警
- [ ] 关键参数和能效指标刷新频率 ≤ 1 分钟

### 故事 4: 能效分析与优化建议

**作为** 运行优化工程师
**我想要** 询问"当前机组能效如何，有哪些优化空间"
**以便** 获取数据驱动的优化建议，指导运行调整

**验收标准:**
- [ ] Agent 调用耗差分析和能效分析小模型
- [ ] 返回当前能效指标与动态基准值/设计值/历史最优值的对比
- [ ] 给出可操作的优化建议（如调整参数方向和幅度）
- [ ] 分析响应时间 < 30 秒

### 故事 5: 逐级分解诊断

**作为** 设备工程师
**我想要** 查看性能偏差的逐级分解结果
**以便** 了解总热耗率/效率偏差中各子系统（压气机、燃烧室、透平）和部件的贡献度

**验收标准:**
- [ ] 基于热力学仿真与偏差传播算法，将总热耗率/效率偏差逐层归因至子系统贡献度
- [ ] 支持进一步分解至部件级（如压气机叶片、燃烧器喷嘴、透平叶片、换热器等）
- [ ] 以层级树状图/瀑布图展示偏差分解结果
- [ ] 偏差贡献度量化到百分比，标识主要贡献项

### 故事 6: 根因推理与诊断结论

**作为** 设备工程师
**我想要** 对性能异常进行根因推理
**以便** 从偏差贡献度和多源特征证据出发，精准定位设备根本原因，获取可解释的诊断结论和维修建议

**验收标准:**
- [ ] 根因推理引擎融合专家规则库与因果图推理算法
- [ ] 利用偏差贡献度与多源特征证据（温度、压力、振动、历史检修记录等）进行因果关联分析
- [ ] 输出 Top-N 候选根因，按置信度排序，附推理路径和证据链
- [ ] 大模型将推理结果转化为自然语言诊断结论和维修建议
- [ ] 支持用户追问和深入讨论（多轮对话）

### 故事 7: 故障诊断辅助

**作为** 设备工程师
**我想要** 描述故障现象后让 Agent 辅助诊断
**以便** 快速缩小故障范围、参考历史案例和检维修知识

**验收标准:**
- [ ] Agent 根据故障现象检索技术知识库 wiki 词条
- [ ] 结合实时监测数据和历史案例给出诊断建议
- [ ] 按可能性排序给出多个候选原因
- [ ] 提供对应的检修方案参考

### 故事 8: 机组对标分析

**作为** 运行优化工程师
**我想要** 查看"本机组与同类型机组运行指标的对比分析"
**以便** 了解本机组运行水平差距和改进方向

**验收标准:**
- [ ] Agent 调用对标分析小模型获取对标数据
- [ ] 以图表形式展示关键指标对比
- [ ] 自动识别差距最大的指标并给出分析
- [ ] 支持按时间段筛选对比范围

### 故事 9: Agent 协同调度

**作为** 系统调度层
**我想要** 根据用户意图自动路由到合适的 Agent 执行
**以便** 用户无需关心 Agent 划分，获得一站式服务

**验收标准:**
- [ ] 调度框架能解析用户意图并路由到正确的 Agent
- [ ] 支持跨 Agent 协同（如预警触发后自动调用诊断）
- [ ] Agent 执行结果能被整合为统一回复
- [ ] 调度日志可追踪，便于调试

## 功能需求

### 核心功能

**功能 1: Agent 调度框架**
- 描述: 统一的用户意图识别、Agent 路由和结果整合框架
- 用户流程: 用户输入 → 意图识别 → Agent 路由 → 执行 → 结果整合 → 展示
- 边界情况: 无法识别意图时提示用户重新描述
- 异常处理: Agent 调用失败时返回错误信息（Demo 阶段简化）

**功能 2: 设备运维 Agent**
- 描述: 封装设备监测数据、预警诊断小模型、技术知识库
- 用户流程: 设备查询/预警解读/故障诊断 → 调用对应小模型或知识库 → 整合分析 → 自然语言回复
- 核心能力:
  - 实时监测数据查询（接入时序数据库）
  - 预警诊断分析（调用预警诊断小模型 API）
  - 故障诊断辅助（检索技术知识库 wiki 词条）
  - 历史案例关联
- 异常处理: 数据不可用时提示并返回最后有效结果（Demo 阶段简化）

**功能 3: 能效监测数据模块**
- 描述: 管理接口对接数据，构建关键参数动态基准值模型，实时计算能效指标，驱动可视化仪表板
- 数据对接:
  - 对接时序数据库和统一 API 接口，获取实时运行数据
  - 关键监测参数: 燃机功率、热耗率、压气机出口压力和温度、透平进气压力和温度、排气温度、燃料流量等
- 动态基准值模型:
  - 基于机组设计工况数据和历史运行数据，建立关键参数随负荷、环境温度等工况变量变化的动态基准曲线
  - 采用回归模型或热力系统简化模型，为每个关键参数生成实时基准值
  - 基准值随工况变化自动调整，替代固定设计值，提高偏差检测灵敏度
- 实时能效指标计算:
  - 发电气耗（m³/kWh）
  - 压气机效率（%）
  - 燃烧效率（%）
  - 透平效率（%）
  - 热耗率（kJ/kWh）
  - 发电效率（%）
  - 联合循环效率（%）
  - 各指标实时值与动态基准值偏差同步计算
- 可视化仪表板:
  - 关键参数实时值与基准值对比趋势图
  - 能效指标仪表盘（当前值 vs 基准值 vs 设计值）
  - 偏差超阈值自动高亮预警

**功能 4: 逐级分解模型与根因推理引擎**
- 描述: 基于热力学原理的偏差逐级分解与大模型驱动的根因推理，实现从性能异常到设备根因的精准定位
- 逐级分解模型:
  - 基于热力学仿真与偏差传播算法，将总热耗率/效率偏差逐层归因
  - 第一级: 总偏差 → 子系统贡献度（压气机、燃烧室、透平）
  - 第二级: 子系统偏差 → 部件级贡献度（压气机叶片、燃烧器喷嘴、透平叶片、换热器等）
  - 输出层级树状分解结果，量化每级贡献百分比
- 根因推理引擎:
  - 融合专家规则库（燃机运维领域知识与故障模式库）与因果图推理算法
  - 利用偏差贡献度与多源特征证据（温度场、压力场、振动频谱、历史检修记录、润滑油分析等）进行因果关联分析
  - 基于因果图进行根因追溯，排除无关因素，收敛候选根因集
  - 输出 Top-N 候选根因，附置信度评分、推理路径和证据链
- LLM 根因分析整合:
  - 大模型将逐级分解结果和根因推理输出转化为自然语言诊断结论
  - 结合检维修知识库生成具体维修建议和处置方案
  - 支持多轮对话追问，工程师可要求进一步解释某个分解路径或根因证据

**功能 5: 运营优化 Agent**
- 描述: 封装能效监测数据模块、耗差分析、对标分析能力，整合逐级分解与根因推理结果，服务于功率优化和热电协调
- 用户流程: 能效查询/优化建议/对标分析/根因诊断 → 调用对应模块 → 结果解读 → 建议输出
- 核心能力:
  - 能效监测与实时指标查询（对接能效监测数据模块）
  - 能效指标分析（调用能效分析小模型 API）
  - 耗差分析（调用耗差分析小模型 API）
  - 机组对标分析（调用对标分析小模型 API）
  - 逐级分解诊断（调用逐级分解模型）
  - 根因推理分析（调用根因推理引擎）
  - 技术知识库检索（检索 wiki 词条，获取检修规程、故障诊断、设备参数等知识）
  - 功率优化与热电协调建议
- 异常处理: 数据/模型不可用时提示用户（Demo 阶段简化）

**功能 6: 运维操作仪表盘**
- 描述: 基于 Vue 3 + Element Plus + ECharts 构建的交互式运维操作中枢。包含 9 个功能页面，首页以燃机机组示意图呈现设备运行全貌，能效监测页以 SCADA 组态图形式展示四大部件实时运行指标与原始监测值，结合各类分析面板和多种触发方式，提供易读易用的运维操作体验
- 页面架构（9 个功能菜单）:
  1. **首页**: 状态总览（发电功率、排气温度、燃料流量、负荷率四项指标卡片）、燃机机组 SVG 示意图（压气机→燃烧室→透平→发电机）、快捷操作按钮（一键执行能效/耗差/对标分析）、最近预警列表、执行日志
  2. **能效监测**: SCADA 组态图 — 顶部横向展示四大部件（压气机/燃烧室/透平/发电机）示意图，每个部件下方对应效率指标面板（当前值、设计值、偏差率）及关联的 SCADA 原始监测值网格；底部展示三大综合指标（热耗率/发电效率/联合循环效率）及其计算参数；附加热耗率趋势图和优化建议
  3. **耗差分析**: 各损失项当前值 vs 设计值柱状图、子系统损失分解瀑布图、损失项明细表
  4. **运营优化**: 综合运营优化分析面板，整合能效/耗差/对标结果
  5. **对标分析**: 本机组 vs 同类机组关键指标对比、差距分析、优势/劣势识别
  6. **预警管理**: 预警列表（按级别着色）、预警详情、处置建议
  7. **根因推理**: 因果图可视化（力导向布局）、候选根因排序表（含置信度和推理路径）、证据链树形图、诊断结论
  8. **数据字典**: 监测参数定义（29 项 SCADA 参数，按四大部件分组）、动态基准值模型配置、对标指标配置，支持手工添加
  9. **模型与知识库**: 小模型接口注册（含联通测试）、技术知识库（基于 Karpathy 知识管理范式的 wiki 词条管理，支持文档上传自动生成词条、原始资料文件查看、内容索引与操作日志查看、知识网络图谱可视化）、专家规则管理、外部向量知识库接入（含联通测试）、因果图管理（节点/边增删，支持模糊搜索选择关联节点）
- SCADA 监测参数体系（29 项）:
  - 压气机: 进口温度 T1、进口压力 P1、出口温度 T2、出口压力 P2、空气流量
  - 燃烧室: 透平进口温度 T3、燃烧室出口压力 P3、天然气瞬时/累计流量、燃气温度、燃气压力、低位热值、排烟含氧量、CO 排放、未燃碳氢
  - 透平: 出口温度 T4、出口压力 P4
  - 发电机: 有功功率、累计发电量
  - 汽机侧: 主蒸汽流量/温度/压力、汽机发电功率
  - 余热锅炉: HRB 进出口烟温、蒸汽温度/压力
  - 其他: 轴向/垂向振动
- 七大能效指标及其 SCADA 计算参数:
  - 发电气耗 ← 天然气瞬时/累计流量、发电机有功功率/累计发电量、燃气温度/压力
  - 压气机效率 ← T1/P1/T2/P2
  - 燃烧效率 ← 天然气流量/热值、空气流量/温度/压力、T3/P3、烟气分析
  - 透平效率 ← T3/P3/T4/P4、燃气流量
  - 热耗率 ← 天然气累计流量/热值、发电功率/电量、温压修正参数
  - 发电效率 ← 3600 ÷ 热耗率
  - 联合循环效率 ← 燃机侧+汽机侧燃料/蒸汽/发电参数、HRB 烟温/蒸汽参数
- 触发机制:
  - **一键触发**: 面板上的操作按钮，点击即调用对应 Agent 执行分析，结果自动回填到面板
  - **定时触发**: 可配置定时任务（如每 1 小时自动执行能效分析、每 15 分钟检查预警状态），结果自动更新到面板并记录历史
  - **条件触发**: 当监测参数越过阈值或小模型产生预警时，自动触发对应 Agent 进行深度分析，结果推送到预警面板并通知相关用户
- Agent 对话入口: 右侧可折叠对话面板，支持自然语言交互
- 交互流程: 触发（点击/定时/条件）→ Agent 执行 → 结果自动回填面板 → 异常时高亮提醒 + 推送通知

**功能 7: 对话交互界面**
- 描述: 自然语言交互入口，作为仪表盘面板操作的补充方式，支持多轮对话和上下文理解
- 适用场景: 面板预设操作无法覆盖的复杂查询、自由探索性分析、追问和深入讨论
- 支持用户以自然语言描述需求
- Agent 回复包含结构化数据（表格、图表）和自然语言解释
- 对话中触发的分析结果同步更新到对应仪表盘面板
- 对话历史记录和回溯

**功能 8: 触发调度引擎**
- 描述: 统一管理一键触发、定时触发和条件触发的调度引擎，与 Agent 调度框架协同工作
- 核心能力:
  - 定时任务管理: 配置 Agent 执行周期（Cron 表达式）、启用/禁用、执行历史查看
  - 条件规则配置: 基于监测数据阈值、预警等级等条件定义自动触发规则
  - 触发结果路由: Agent 执行结果自动回填到对应仪表盘面板，触发通知推送
  - 执行日志: 记录所有触发事件、Agent 调用链和结果，支持回溯审计

**功能 9: 技术知识库系统**
- 描述: 基于 Karpathy 知识管理范式构建的文件驱动知识体系，支持文档上传自动提取知识、结构化 wiki 词条管理、知识图谱可视化，并与 Agent 对话系统深度集成
- 知识库目录结构:
  ```
  knowledge/
  ├── raw/          # 原始资料层：只读，大模型绝不修改
  │   ├── *.*       # 用户上传的原始文档（docx/pptx/pdf/xlsx/md）
  │   ├── *.md      # 文档解析后的 markdown 转换件
  │   └── assets/   # 提取的图片附件
  ├── wiki/         # 知识库 Wiki 层：大模型全权维护
  │   ├── content/  # 内容摘要词条
  │   ├── entity/   # 实体词条（设备/部件）
  │   ├── concept/  # 概念词条（参数/指标/规程/技术/规则）
  │   ├── comparative/ # 对比分析词条
  │   ├── overview/ # 总览综述词条
  │   ├── index.md  # 内容索引（自动更新）
  │   └── log.md    # 操作日志（仅追加）
  ├── CLAUDE.md     # 知识库规则范式
  └── 知识库方法说明.md # 体系架构说明
  ```
- 核心能力:
  - **文档入库**: 上传 docx/pptx/pdf/xlsx/md → 解析为 markdown → LLM 自动提取知识 → 生成 10-15 条 wiki 词条
  - **wiki 词条管理**: 5 种词条类型（内容摘要/实体/概念/对比分析/总览综述），支持搜索、筛选、分页浏览、详情查看、删除
  - **原始资料查看**: 浏览 raw/ 目录下的上传文件，.md 文件在线查看内容，其他格式支持下载
  - **内容索引与操作日志**: 实时查看 wiki/index.md（内容索引）和 wiki/log.md（操作日志）
  - **知识图谱可视化**: 基于 wiki 词条间的标签交集、分类关联、显式引用构建关系图谱，力导向布局展示知识网络
  - **Agent 知识检索**: wiki_search 工具注册到运营优化 Agent，智能助手对话自动获得知识库检索能力
- 词条格式: 每个 wiki 词条为独立 markdown 文件，含 YAML frontmatter（id/title/type/category/tags/equipment/severity 等）+ markdown 正文
- 数据迁移: 系统首次启动时，自动将现有 mock 检维修知识数据迁移为 wiki 初始词条

## 技术约束

### 性能
- 预警类查询响应 < 5 秒（实时性要求高）
- 简单状态查询 < 10 秒
- 综合分析查询 < 30 秒
- 支持同时 3-5 人使用（Demo 规模）

### 安全
- Demo 阶段暂无特殊安全合规要求
- 系统仅做分析和建议，不直接控制设备（安全边界）
- 数据不出厂，本地部署

### 集成
- **时序数据库**: 存储燃气轮机实时监测数据（温度、压力、振动、功率等）
- **统一 API 接口**: 已部署小模型（预警诊断、能效分析、耗差分析、对标分析）的调用入口
- **技术知识库**: 基于 Karpathy 范式的文件驱动知识管理体系（原始文档 + 结构化 wiki 词条），支持文档上传自动入库和知识检索
- **设计工况数据**: 机组设计参数、热力系统设计数据，用于构建动态基准值模型
- **专家规则库**: 燃机运维领域故障模式、因果规则和诊断经验知识

### 技术栈
- **后端**: Python 3.12 (FastAPI) + LangChain Agent 框架
- **LLM**: 本地开源模型（Qwen / ChatGLM 等），通过 OpenAI 兼容接口接入（LangChain ChatOpenAI）
- **前端**: Vue 3 + TypeScript + Vite
- **UI 框架**: Element Plus
- **图表可视化**: ECharts（vue-echarts，趋势图、柱状图、力导向图、树状图、瀑布图）
- **数据源**: 当前为 Mock 数据（模拟 SCADA 29 项监测参数），后续替换为时序数据库 + 统一 API 接口
- **计算引擎**: 热力学仿真模型（偏差传播）、因果图推理算法
- **触发调度**: APScheduler（定时任务、条件触发）
- **HTTP 客户端**: httpx（模型联通测试）、axios（前端 API 请求）
- **前后端通信**: WebSocket（对话流式推送）+ REST API（分析请求/结果），Vite 开发代理
- **数据管理**: Pydantic Settings（后端配置）、Vue reactive stores（前端状态）

### Phase 3: 工作流编排引擎 + Agent 完善

#### 3.1 可视化工作流编排引擎（LangGraph + DAG 可视化编辑器）

基于 LangGraph 构建通用的分析工作流网页编排工具，支持拖拽式组装分析链路，用户无需编程即可定义从数据采集到结论输出的完整分析流程。

**架构设计：**

- 后端：基于 LangGraph 的 StateGraph 构建 DAG 工作流引擎，每个节点对应一个可执行组件，边定义数据流向和条件路由
- 前端：基于 Vue Flow（或类似的 DAG 可视化库）构建画布式编排界面，支持节点拖拽、连线、参数配置、实时预览
- 存储：工作流定义序列化为 JSON Schema，支持保存、加载、版本管理

**可编排组件清单：**

| 分类 | 组件名称 | 功能说明 |
|------|----------|----------|
| 输入 | 用户输入 | 接收用户自然语言提问或参数输入 |
| 输入 | 指标参数选取 | 从数据字典中选取监测参数或对标指标，作为后续分析的数据源 |
| 分析 | 意图识别（LLM） | 调用大语言模型识别用户意图，决定后续路由 |
| 分析 | 小模型调用 | 从已注册的小模型列表中选取模型执行分析（能效/耗差/对标/预警） |
| 分析 | 推理分析 | 基于指标参数、专家知识库、专家规则进行因果推理和综合研判 |
| 分析 | 代码执行 | 执行用户自定义 Python 脚本（用于自定义计算逻辑） |
| 知识 | 专家知识库 | 检索检维修知识库（支持全文/向量检索） |
| 知识 | 专家规则 | 匹配并应用专家规则（条件→结论→建议措施） |
| 输出 | 结果输出（LLM） | 调用大语言模型生成自然语言分析报告 |
| 输出 | 数据输出 | 将中间结果或最终结果输出为结构化数据（JSON/表格） |
| 通用 | 条件分支 | 根据条件判断走不同分支（如：效率 > 阈值 → 正常路径，否则 → 异常路径） |
| 通用 | 循环 | 对列表数据逐项执行子流程 |
| 通用 | 迭代 | 反复执行子流程直到满足终止条件（如：逐步缩小根因范围） |
| 通用 | 问题分类器 | 将用户问题分为预定义类别，路由到不同处理链路 |
| 通用 | 列表操作 | 对数据列表进行过滤、排序、聚合、映射等操作 |
| 通用 | 变量存储 | 在工作流中存取中间变量，跨节点传递数据 |

**预设工作流模板：**

1. **能效异常诊断流**：用户输入 → 意图识别 → 实时监测数据获取 → 能效分析模型调用 → 指标偏差判断（条件分支）→ 正常路径：输出报告 / 异常路径：触发耗差分析 → 逐级分解 → 专家规则匹配 → 根因推理 → 结果输出
2. **预警响应流**：预警触发 → 预警详情获取 → 关联参数查询 → 专家知识库检索 → 处置建议生成 → 结果输出
3. **定期对标分析流**：定时触发 → 对标模型调用 → 差距分析（条件分支）→ 优势/劣势分类 → 优化建议生成 → 报告输出
4. **自定义诊断流**：用户自由编排，按需组合各类组件

### 术语表
- **Agent（智能体）**: 基于 LLM 的自主任务执行单元，能理解意图、调用工具、整合结果
- **小模型**: 已部署的专业分析模型（预警诊断、能效分析、耗差分析、对标分析）
- **SCADA**: Supervisory Control And Data Acquisition，数据采集与监控系统，本系统中指 29 项燃机实时监测参数
- **组态图**: 以图形化方式展示设备系统结构，将实时监测数据和计算指标叠加到对应设备位置
- **时序数据库**: 存储燃气轮机实时监测数据的数据库
- **动态基准值模型**: 基于设计工况和历史数据，为关键参数建立随工况变化的基准曲线，替代固定设计值
- **耗差分析**: 分析机组各项损失（压气机效率、燃烧器效率等）对整体能效的影响
- **逐级分解模型**: 基于热力学仿真与偏差传播算法，将总偏差逐层归因至子系统和部件级贡献度
- **LangGraph**: LangChain 生态中的工作流编排框架，基于 StateGraph 构建 DAG（有向无环图），支持条件路由、循环、状态管理
- **工作流编排**: 通过可视化拖拽界面组合预定义组件（LLM 调用、小模型、知识库检索等）形成自动化分析链路
- **DAG**: Directed Acyclic Graph，有向无环图，工作流编排的底层数据结构，定义组件间的执行顺序和数据流向
- **根因推理引擎**: 融合专家规则库与因果图推理算法，利用偏差贡献度和多源证据进行根因追溯
- **因果图**: 描述设备参数间因果关系的有向图，用于推理故障传播路径
- **偏差传播**: 将总体性能偏差沿热力系统因果链逆向追溯，分解至各环节贡献度
- **热电协调**: 燃气轮机热电联产机组的热负荷与电负荷优化分配
- **对标分析**: 将本机组运行指标与同类机组或设计值进行对比分析
- **向量知识库**: 基于嵌入模型的文档检索系统，支持自然语言语义搜索
- **燃机机组示意图**: 以图形化方式呈现燃气轮机系统全貌（压气机、燃烧室、透平、发电机、余热锅炉等），叠加实时运行数据和状态着色
- **技术知识库**: 基于 Karpathy 知识管理范式构建的文件驱动知识管理体系，用户上传文档后由 LLM 自动提取知识并生成结构化 wiki 词条
- **Wiki 词条**: 技术知识库中的知识单元，为独立 markdown 文件，包含 YAML frontmatter（元数据）和正文内容，分 5 种类型：内容摘要、实体、概念、对比分析、总览综述
- **知识图谱**: 基于 wiki 词条间的标签交集、分类关联、显式引用关系构建的知识网络可视化，以力导向布局展示词条关联
